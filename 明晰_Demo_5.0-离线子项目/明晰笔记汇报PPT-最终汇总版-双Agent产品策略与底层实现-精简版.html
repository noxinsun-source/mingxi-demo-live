同一份内容，对你意味着什么，取决于你此刻要完成的任务。 目标、意义与最终判断，是最不该被 AI 替代的一环。

因此，任务意图必须由用户确认，而不能由模型静默代写。

长期互动后，AI 可以学习个人语境并提出意图建议；角色如何分配，仍由用户随情境调整。

不是 Pi Agent，
而是自研领域 Harness。

当前代码未引入 Pi / LangChain / Mastra 等通用 Agent 编排框架。模型只是可替换的推理层；真正定义 Agent 行为的，是仓库自有的上下文、状态循环、结构化契约与确定性门控。

01

产品交互层

Web App、宿主 Plugin / Skill，承接用户目标、笔记与人工修订。

02

领域 Harness

组装上下文、系统策略、预算、状态与循环；这是 Agent 的核心底座。

03

Provider 适配层

OpenAI-compatible、Ollama 或 Codex / Claude 宿主推理，可替换而不改领域规则。

04

结构化提案

模型输出 AgentPlan / AgentGraphDraft，而不是任意执行代码或直接写库。

05

确定性门控

Schema、Compiler、证据、预算、版本 CAS 与停止条件共同裁决。

06

状态与交付层

IndexedDB / JSON / D1，配合 Run API、MCP 与 SSE 留存真实结果。
